**ปัญหาที่พบ**
- ชื่อคอลัมน์มีช่องว่างต่อท้าย เช่น `AMPHUR_NAME     `, `MOO_ID    ` ต้อง trim ก่อนใช้
- ค่าข้อความเติมช่องว่างให้ยาวเท่ากัน (fixed-width) เช่น `อุทกภัย      ` ต้อง trim
- ปีที่ไม่มีเหตุการณ์เป็นช่องว่าง (`'     '`) ไม่ใช่ `0` หรือ NULL
- ค่าในคอลัมน์ปี (`Y2562`-`Y2567`, สูงสุด 12) หมายถึงจำนวนครั้งที่เกิดอุทกภัยในหมู่บ้านนั้นในปีนั้น
- **ปี 2567 มีข้อมูลเพียง 207 แถว** เทียบกับปีอื่นหลายหมื่นแถว แปลว่าข้อมูลปี 2567 ยังไม่ครบ ไม่ควรนำไปเทียบกับปีอื่นโดยตรง
- ไม่มีข้อมูลความลึกน้ำท่วมหรือความเสียหายรายหมู่บ้านในไฟล์นี้ (มีแค่ว่าเกิดเหตุกี่ครั้ง) จึงตอบ "เมื่อระดับน้ำใกล้เคียงกัน" ใน Q1 ได้เพียงบางส่วน

### 2.2 สถิติอุทกภัยรายหมู่บ้านชุดย่อย (`dpm-gd015__1.csv`)

| หัวข้อ | รายละเอียด |
|---|---|
| หน่วยงาน | ปภ. (ชุด `dpm-gd015`) |
| หน้าชุดข้อมูล | https://catalog.disaster.go.th/dataset/dpm-gd015 |
| รูปแบบ | CSV, UTF-8 มี BOM |
| ขนาด | 29,999 แถว x 18 คอลัมน์ (6.4 MB) |
| ขอบเขต | 37 จังหวัด (จาก 77) |
| โครงสร้างคอลัมน์ | เหมือนข้อ 2.1 ทุกคอลัมน์ |

**ข้อค้นพบสำคัญ:** ตรวจเทียบแล้ว `MOO_ID` ทั้ง 29,999 รายการใน `dpm-gd015__1.csv` **อยู่ในไฟล์ `STATISTIC_FLD.xlsx` ทั้งหมด** (เป็นเซตย่อย) และไฟล์นี้มีเพียง 37 จังหวัด คาดว่าเป็นการดาวน์โหลดที่ถูกตัดที่ประมาณ 30,000 แถว

**ผลกระทบและข้อเสนอ**
- ถ้านำสองไฟล์มา union กันโดยไม่ตรวจ จะ**นับซ้ำ** 29,999 หมู่บ้าน
- ให้ใช้ข้อ 2.1 เป็นแหล่งหลักของข้อมูลหมู่บ้าน และเก็บข้อ 2.2 ไว้เป็นข้อมูลเทียบ (cross-check) เท่านั้น หรือตัดออกจาก pipeline ถ้าไม่ได้ใช้

**ปัญหาที่พบ**

- ค่า `value` เป็นข้อความ เช่น `.00` ต้องแปลงเป็นตัวเลข
- 1,725 แถวมีหมายเหตุในคอลัมน์ `attribute` เช่น "ศูนย์ยกกำลังดับเบิลยู หมายถึง ข้อมูลจากการสำรวจตัวอย่างมีค่าเป็น 0" (1,681 แถว) และ "ปัดเศษแล้วเป็น 0" (43 แถว, ติดลบ 1 แถว) ศูนย์สองแบบนี้มีความหมายต่างกัน (ตัวอย่างสำรวจไม่พบ กับค่าจริงที่น้อยจนปัดเป็น 0) ไม่ควรถือเป็น "ศูนย์จริง" แบบเดียวกันทั้งหมด
- **ปีไม่ตรงกับ proposal:** proposal ระบุว่าใช้ปี 2564-2566 แต่ไฟล์จริงมี 2566 และ 2568 และข้อมูลน้ำท่วมมีถึง 2567 เท่านั้น จึง**ซ้อนทับกันเพียงปี 2566 ปีเดียว**

## 4. ข้อจำกัดที่กระทบการวิเคราะห์ (Data Gap)

1. **ไม่มีข้อมูลระยะเวลาฟื้นตัวโดยตรง** ในทุกชุดที่นำเข้า Q2 จึงทำได้เพียงเทียบขนาดความช่วยเหลือกับความถี่/ขนาดผลกระทบ ห้ามสรุปว่าการช่วยเหลือทำให้ฟื้นตัวเร็วขึ้น
2. **ปีซ้อนกันน้อย:** น้ำท่วมมี 2562-2567, รายได้รายจังหวัดมีเฉพาะ 2566 และ 2568, วงเงินช่วยเหลือมีเฉพาะ 2564 จึงเทียบข้ามชุดแบบตรงปีได้แทบไม่มี ปีที่ต้องตัดสินใจเลือกเป็นเรื่องหลักของ Transformation
3. **ระดับพื้นที่ต่างกัน:** หมู่บ้าน (2.1) / ตำบล (2.5) / อำเภอ (2.4) / จังหวัด (2.3, 2.7) / ภาค (2.8) การ join ต้องรวมขึ้นไประดับจังหวัดเป็นอย่างต่ำ
4. **ข้อมูลระดับจังหวัดเดียว:** 2.4 (หนองคาย), 2.5 (พังงา), 2.6 (ยโสธร) เป็นกรณีศึกษา ไม่ใช่ตัวแทนทั้งประเทศ
5. **ข้อมูลที่ได้ไม่ใช่ "จำนวนครัวเรือนที่ได้รับเงินเยียวยา" โดยตรง** แม้ proposal จะระบุชื่อชุดข้อมูลนั้น ไฟล์ที่ได้ (2.4, 2.5) เป็นจำนวนครัวเรือนที่ได้รับผลกระทบ ในรายงานควรใช้ถ้อยคำให้ตรงกับข้อมูลจริง
